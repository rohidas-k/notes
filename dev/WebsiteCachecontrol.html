Website Cache control

When you run vite build, it automatically appends a unique content hash to the end of every JavaScript and CSS file (e.g., react-icons-b7a9f2.js). Because the filename changes every time the code changes, these files are immutable—meaning you can safely tell the browser and network networks (like Cloudflare) to cache them forever.

To actually enforce this caching on the network level, you need to configure your hosting environment's HTTP Headers. Since you are using Cloudflare Pages (.pages.dev) for the frontend and possibly Apache for your PHP backend, here is how to handle both.

Option 1: Cloudflare Pages (For your .pages.dev deployment)

Cloudflare Pages allows you to set custom network cache rules using a simple text file.

  1. Inside your React project, go to your public folder.
  2. Create a file named exactly _headers (no file extension).
  3. Add the following rules:

Plaintext

# 1. Cache all Vite hashed assets (JS, CSS, Images) for 1 Year

/assets/*

  Cache-Control: public, max-age=31536000, immutable

# 2. NEVER cache the index.html (Forces browser to check for new hashes)

/*

  Cache-Control: no-cache, no-store, must-revalidate

How it works:

When a user visits your site, their browser will download index.html fresh every time. That HTML file tells the browser which hashed JS files to load. Because the /assets/* folder is set to immutable for 1 year (31536000 seconds), the browser and Cloudflare's Edge CDN will load the JS files instantly from memory without ever hitting the server again.

Option 2: Apache Server (If you move the frontend to your cPanel/PHP host)

If you decide to host the React build on the same Apache server as your PHP backend, you handle network caching via the .htaccess file.

Place this .htaccess file in the root of your deployed dist folder:

Apache

<IfModule mod_headers.c>

    # 1. Cache all hashed assets in the Vite /assets/ folder for 1 Year

    <FilesMatch "\.(js|css|woff2|png|jpg|jpeg|gif|svg)$">

        Header set Cache-Control "public, max-age=31536000, immutable"

    </FilesMatch>

    # 2. Prevent caching of index.html so updates are immediate

    <FilesMatch "^index\.html$">

        Header set Cache-Control "no-cache, no-store, must-revalidate"

        Header set Pragma "no-cache"

        Header set Expires 0

    </FilesMatch>

</IfModule>

# Optional: Enable GZIP/Brotli compression for even faster network delivery

<IfModule mod_deflate.c>

    AddOutputFilterByType DEFLATE application/javascript text/css text/html

</IfModule>

Option 3: Client-Side Caching (Service Workers)

If you want the JS files to be cached so aggressively that the website can literally load offline, you can install Vite's PWA plugin. This uses a Service Worker to intercept network requests and serve JS files directly from the user's local disk cache.

1. Install the plugin:

Bash

npm install vite-plugin-pwa -D

2. Add it to vite.config.js:

JavaScript

import { defineConfig } from 'vite';

import react from '@vitejs/plugin-react';

import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({

  plugins: [

    react(),

    VitePWA({

      registerType: 'autoUpdate',

      workbox: {

        globPatterns: ['**/*.{js,css,html,ico,png,svg}'] // Caches everything generated in dist

      }

    })

  ]

});

This strategy combined with the _headers file ensures your application loads instantly on repeat visits, drastically reducing bandwidth and improving your Google Core Web Vitals score.
